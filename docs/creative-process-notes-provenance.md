# Creative Process Notes — implementation provenance

- **Origin:** Jacob Ross requested a paste-friendly, long-form Style Prompt / Instrumentation / Production Notes / Creative Direction field in Upload and Edit Work on 2026-09-12. The creator's own words are the input; no AI generation is required.
- **Starting source:** `Whisperer217/living-nexus_provenance` main `c6a803d5`. `/upload` redirects to the active `/manifest` MusicEnvironment. The older UploadPage remains in source, while CreativeDrawer is the shared Edit Work surface. HAAI instrumentation and origin declarations already exist but have a separate authorship purpose.
- **Derivative:** a nullable `songs.creativeProcessNotes` text field, bounded to 10,000 characters in the API and textareas. Both active Manifestation Studio and the legacy UploadPage submit it; the owner-aware draft reader rehydrates it, and CreativeDrawer loads it from the owner-scoped reader before enabling that input. Unrelated metadata saves omit the field until hydration succeeds, avoiding an accidental clear. Upload stores it for Draft or Published works; later status changes do not touch it.
- **WID boundary:** the notes are classified as editorial metadata in PreparedWorkRegistration. They go to `songs.upload` but not `serializePreparedWorkWidPayload`, so adding or editing them does not reseal or replace the original WID. A later edit appends a Work event with presence and WID reference only, not the note text.
- **Visibility and AI permission:** this column follows the existing Work metadata API visibility; public Work readers currently return whole song rows. Creators should treat the text as public metadata on a published Work. Storing or publishing it does not change `aiConsent` or authorize Nexus context or provider access. A private creator notebook would require a distinct access policy and storage boundary.
- **Migration:** Drizzle schema and custom migration `0134_creative-process-notes.sql` add one nullable column; no backfill or WID rewrite. The journal/snapshot are advanced to 0134. `drizzle-kit check` passed using a schema-only local URL; no live database migration was run.
