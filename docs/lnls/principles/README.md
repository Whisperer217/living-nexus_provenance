# Living Nexus — Engineering Principles
## LNLS v1.0 · Section 9

---

## The Priority Sequence

When uncertainty exists about what to build next, this sequence governs:

```
Identity → Domain → Manifestation → Provenance → Discovery → Distribution → Artifact
```

A feature that strengthens Identity (Creator profiles, WID system, authentication) takes priority over a feature that strengthens Discovery (search, explore, recommendations). A feature that strengthens Provenance takes priority over a feature that strengthens Distribution.

---

## The Operational Doctrine

| Principle | Meaning |
|---|---|
| Repair over expansion | Fix what is broken before adding what is new |
| Clarity over novelty | A clear, simple feature beats a clever, complex one |
| Creator ownership over platform dependency | The Creator can always export their data |
| Provenance over popularity | Provenance integrity is the primary metric |
| Exportability over lock-in | Every record is exportable in an open format |
| Physical reality over cloud abstraction | The Creator's real identity anchors the digital record |
| Stable architecture over rapid feature accumulation | A platform that works beats a platform that impresses |

---

## The Deferral Rule

If a proposed feature increases complexity without strengthening Creator Domains, Identity, Provenance, Discovery, Distribution, or Artifacts, it should be deferred.

---

## The Language Rule

Every word in the platform's UI is an engineering decision. The word "Follow" is not equivalent to the word "Witness." They produce different behavior in the user, different expectations, and different relationships. The canonical vocabulary in this specification is not optional. It is a constraint on every UI string in the codebase.
