# Global Player volume and lifecycle follow-up

- **Origin:** Jacob Ross's 2026-09-12 request to put expanded-player volume at the distal edge and clean up playback stability, including [Player stability issue #1](https://github.com/Whisperer217/living-nexus_provenance/issues/1). Implemented by Codex on `fix/global-player-volume-stability` from `main` at `58049283dddad5c12d0fd3a71c8ce1e1418e9f69`.
- **What existed:** `PlayerProvider` already owned a singleton audio element, a single long-lived listener effect, one restore effect, and session-backed queue/volume state. Issue #1's requested duplicate-effect removal and new `tracksRef` do not describe this current source; its later owner comment reports the phase clean. The expanded mobile `GlobalPlayer` placed mute buttons on both ends of one slider. When muted, `setVolume` cleared the React mute flag without clearing `audio.muted`.
- **What changed:** expanded desktop volume is the distal action in its utility row. Expanded mobile volume has one mute button at the far end and a named slider with a 40px touch target while its visual track stays 6px. `setVolume` clears both the DOM and React mute state; separate effects synchronize volume and mute with the singleton audio element, leaving media listener binding independent of UI volume changes. The existing local UI cache now also persists mute preference across refresh/reopen, alongside volume.
- **Boundary:** no new audio element, route, provider, Registry permission, or context authority. No schema or data migration. The current audio track remains authoritative; `visTrack` remains presentation only.
- **Verification:** TypeScript check and production build passed. Focused player composition, continuity diagnostics, access-route, and queue contracts passed 16/16. Authenticated live playback and physical-device interruption behavior were not exercised locally.
